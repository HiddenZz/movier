# Код-стайл dart&flutter

Главное правило - код стайл максимально должен быть приближен SDK flutter с приоритетом на ванильные решения

## code-style

### Dart

- Везде, где есть возможность указать явный дженерик - укажи джнерик для читаемости
- final, const автоопределяют тип переменной, поэтому указывать тип не нужно
- в замыкания тип не указывается
- Используй паттерн матчинг там где это возможно применить:  ```final Object someValue = ...; if(someValue final String someValue when someValue.isNotEmpty)``` и другие возможности паттрен-матчинга dart;
- Глобальные хелпер методы без обертки ввиде класса называй начиная с символа *\$*: ```helpSomeMethod()```;
- Для разделениев подтипов в названии классов используй *\$* ```sealed class SomeBaseClass{} class Basic$SomeBaseClass{}```

### Flutter

- Если необходимо композировать верстку - разделдяй на отделньные виджеты - классы
- Не используй билд методы
- Для сложной верстки не забывай про возможность реализовать все через RenderObject; CustomMultiChildLayout; CustomSingleChildLayout; Flex; etc
- Больше работай с контекстом, лучше создать обертку и вынести какие то значения по контексту, чем передавать в глубь через множесво конструктов
- Не принебрегай разными методами работы с контекстом: ```context.find*```, ```context.get*```
- Не используй setState на больших виджетах, чище и лучше локализовать перерисовку с помощью Listenable
- Не забывай про то, что многие виджеты принимают repaint:Listenable. Используй для оптимизаций перерисовок
