# CLAUDE.md

## mobile

клиентский модуль movier, которые представляет из себя каталог фильмов с возможностью скачать на устройство, скачать на сервер или просматривать в реал тайм.

## architecture

feature first подход; Каждая фича выносится в отдельную папку в feature. Фича делится на controller; data; model; widget;
Общие для *всего* компоненты выносятся в common: env, router, theme, widget; Общим не считается виджет или бизнес-логика которая используется в двух фичах. Например, слушатель одной фичи не считается общим.
Все переменные, которые оставляются как глобальные константы/приватные константы которые теоретически могли бы в дальнейшем быть изменены, должн быть вынесены в конфиг файл

## platforms

Целевые платформы — iOS, Android и macOS

Платформенные различия резолвятся в одном месте — `common/env/platform_capabilities.dart`.
Вместо `if (Platform.isMacOS)` по дереву спрашивай про возможность
(`supportsOrientationLock`, `supportsScreenBrightness`, `usesPointerInput`).
Внутри `defaultTargetPlatform`, а не `dart:io`: в модуле есть каталог `web/`.

Сеть macos ходит через `com.apple.security.network.client`
в обоих entitlements-файлах, plain HTTP к `localhost` разрешён через
`NSAllowsLocalNetworking` в `macos/Runner/Info.plist`.

## deps

**navigator** - кастомный навигатор в /common/navigator/; Добавляй роуты по необходимости, если в навигаторе нет необходимого апи для решения проблемы - расширяй отдельной задачей;
**controller** - control использует блок подход с стейтами. Поддерживает апи конкурентности и имеет дополнительные бонусы для логирования происходящего с помощью мета полей в обработчике *handle*. Бизнес-логика должна быть наполнена логами и метой по необходимости, каждый стейт должен содержать поле *message* для контекста; Обработка ошибок происходит с помощью глобального ErrorUtil в который принимает object и по типу маппит читаемую ошибку в виджет слое; По необходимости заводи дополнительные типы ошибок;
**Ошибки** - для отображения читаемых ошибок пользователю используется глобальный абстрактный класс наполненный статическими хелпер методами ErrorUtil; Концепция его работы подразумевает передачу в один метод errorToString какой то Object, где происходит паттерн матчинг для определения типа ошибки;
**logger** - используется l c разными уровнями логирования, добавляй логи там где это уместно, не раскидывай везде подряд;
**uikit** - общие компоненты выноси в common/ui_kit; Если компонента нужного нет, переключись на реализацию, можешь использовать figma-mcp для поиска спецификации нужного комопнента;
**localization** - в проекте испольузется локализация с помощью l10n и с поддержкой двух языков Ru, Eng; Первод осуществялется сразу по мере добавления новых строк;

## Критические правила

Перед добавлением нового функционала убедись в том что server часть поддерживает такое api. Если нужного функционала нет, переключайся на реализацию server части. Всегда сверяй контракты апи и бэкенда для добавления дата-слоя и новых моделей;

## Комментарии

Оставляй краткие комментарии там, где это поможет объяснить предназначение класса/функции/поля. Не растягивай описание, на то почему был выбран такой подход при реализации, только краткое описание какую это проблему решает. По необходимости оставляй рефы на другие классы. Должен поддерживаться стиль dartdoc
В особо сложных функциях какого-то конктракта можешь оставить кратки пример кода
